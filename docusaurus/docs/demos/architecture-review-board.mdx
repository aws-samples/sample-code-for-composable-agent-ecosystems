# Architecture Review Board

A guided walkthrough of a complete Tessera ecosystem, start to finish. The
**Architecture Review Board** ecosystem convenes a panel of senior reviewers that
pressure-tests a proposed AWS solution architecture from security, reliability,
cost, data/privacy, and operations angles — letting the submitter defend points,
preserving dissent, and returning a defensible **go / go-with-conditions / no-go**
verdict.

Unlike a standard orchestrated workflow, this ecosystem uses Tessera's **quorum**
model: reviewers are empanelled from a catalog of personas, deliberate over
multiple rounds, and sketch a shared whiteboard as they reason.

The four short clips below follow the full loop: **build** the ecosystem in the
visual Builder, **run** it, **watch** the live deliberation, and **review** the
verdict. Each video is click-to-play.

## 1. Build the ecosystem

Compose the ecosystem in the visual Builder — set the quorum empanelment, the
dimensions the panel must cover, and the verdict scale, then save and deploy. No
code; the Builder compiles it into a runnable review. For the full walkthrough, see
[Build an ecosystem](../guides/build-an-ecosystem.md).

## 4. Review the verdict

When deliberation concludes, the board returns a defensible verdict —
**defensible**, **defensible with conditions**, or **indefensible** — stating what
it fails against, the indefensible elements, and the remediation. Dissent is
preserved rather than averaged away. For how to read a run and iterate on it, see
[Run and review](../guides/run-and-review.md).
