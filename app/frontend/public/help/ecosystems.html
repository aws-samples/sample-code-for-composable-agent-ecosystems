Ecosystem Grid

The main Ecosystems view shows all available ecosystems as cards. Each card displays:

  • Strategy badge — orchestrated (DAG) or choreography (event-driven)
  • Agent count — number of agents in the ecosystem
  • Name and description — what the ecosystem does
  • System badge — 🔒 SYSTEM ecosystems are managed by the system and cannot be edited or deleted

To select an ecosystem, choose a card. The action bar at the top activates once an ecosystem is selected.

Action Bar

With an ecosystem selected, the action bar provides:

ButtonAction
▶ RunOpen the run modal to launch the ecosystem with a mission and inputs
📁 FilesManage documents attached to this ecosystem (see Files)
📜 HistoryView past runs — statuses, timestamps, and the ability to redrive failed runs
⚡ OptimizeTrigger AI analysis of recent runs to propose quality/time/cost improvements

Launching a Run

Choosing ▶ Run opens a conversational launch dialog. Instead of a single mission box, a run planner interviews you — one focused question at a time — to build a complete brief for the ecosystem, and you can attach files to any run. See Running → Starting a Run for the full flow.

Prefer to type the mission yourself? Switch to "Type it myself" in the dialog for a plain mission box.

Run History

The History modal shows all past runs for the selected ecosystem with:

  • Status — succeeded, failed, or running
  • Timestamp — when the run started
  • Redrive — for failed runs, resume execution from the point of failure
  • Resume from here — choose any node in a run's DAG to start a new run that reuses completed upstream steps (works for failed and succeeded runs)
  • Optimize — trigger the optimizer against a specific past run's telemetry

Optimizing an Ecosystem

The ⚡ Optimize button triggers the platform optimizer, which:

  1. Loads telemetry from recent runs (agent durations, tool usage, grounding results)
  2. Runs quality/time/cost analysts to identify improvements
  3. Produces a patch — proposed changes to the ecosystem YAML
  4. Presents the patch in an apply panel where you can review and accept changes
System-managed ecosystems (🔒) cannot be optimized — they are managed by the system itself.

Authorization & Sharing

Every ecosystem has an owner — the user who created it. Access is enforced by AWS Verified Permissions (Cedar policies):

  • Owner — full control: run, edit, share, delete.
  • Admins — can manage any ecosystem.
  • Others — can only see/run an ecosystem if it has been shared with them (or a group they belong to).
  • System (🔒) — platform-managed; not editable via the UI by anyone.

To share, select an ecosystem and choose 🔗 Share. In the Sharing dialog you:

  1. Pick a user or group as the principal
  2. Choose a permission level:
    • run — launch runs only
    • edit — modify the configuration
    • full — edit plus manage sharing
  3. Grant — the principal appears under Current Access; revoke anytime with ✕

Owners see an access summary on the ecosystem card. Admins can review and manage all sharing from Admin → Sharing.

Platform vs User Ecosystems

System-managed ecosystems are shipped with Tessera and maintained by the Tessera team. They have a 🔒 SYSTEM badge and cannot be edited, deleted, or optimized via the UI.

User ecosystems are created via the Builder or AI suggestion. You have full control: edit, optimize, attach files, and delete.
