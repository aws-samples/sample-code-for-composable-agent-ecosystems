Quality Features Overview

Tessera applies multiple layers of verification designed to improve output reliability. You can configure these per ecosystem in the Builder.

🛡️ Challenger Agent
Auto-injected agent that stress-tests all upstream findings. Looks for logical gaps, unsupported claims, and contradictions.
📋 Report Agent
Auto-injected final agent that synthesizes all findings — including the challenger's critique — into a coherent, faithful report.
🔍 Internal Grounding
Amazon Bedrock Guardrails checks each agent's claims against the evidence it actually has: upstream agent outputs and its own tool-call results.
🌐 External Grounding
Time-sensitive claims are verified via web search. Each claim gets a verdict: verified, unverified, or contradicted.

How It Works During a Run

Quality checks happen automatically between agent layers:

  1. Agent executes — produces output with structured findings
  2. Schema validation — output must contain STRUCTURED FINDINGS and OPEN QUESTIONS sections (hard requirement, no fallback)
  3. Internal grounding — Amazon Bedrock Guardrails checks claims against available evidence. Shown in the activity strip as "Verifying findings"
  4. External grounding — time-sensitive claims are extracted and verified via web search. Shown as "External grounding (web verification)"
  5. Next layer proceeds — downstream agents receive verified upstream output

Challenger Agent

The challenger is a special agent injected after all leaf and synthesizer agents complete. It:

  • Receives all upstream agent outputs
  • Actively looks for weaknesses: unsupported claims, logical inconsistencies, missing perspectives
  • Produces its own STRUCTURED FINDINGS highlighting issues
  • The report agent must faithfully surface the challenger's critique
The challenger uses the same model as other agents but with an adversarial prompt. It genuinely tries to break the analysis rather than rubber-stamping it.

Internal Grounding

Uses Amazon Bedrock Guardrails contextual-grounding to verify claims:

  • Grounding source — upstream agent prose + the agent's own tool-call results
  • What it catches — claims that don't appear in any evidence, hallucinated numbers, fabricated sources
  • Result — claims flagged as unsupported are visible in the grounding check output

External Grounding

For claims about the real world (prices, dates, events, "recent" or "current" statements):

  1. Time-sensitive claims are extracted from agent output
  2. Each claim is searched via web search
  3. A Sonnet 4 evaluator compares the claim against search results
  4. Each claim receives a verdict: verified, unverified, or contradicted

Structured Findings Format

Every agent must produce output containing:

  • ## STRUCTURED FINDINGS — numbered findings with confidence level (HIGH/MEDIUM/LOW) and evidence citations
  • ## OPEN QUESTIONS — unresolved questions or areas needing further investigation

If an agent fails to produce these sections, the run reports an error rather than continuing with incomplete data.

Toggling Quality Features

In the Builder's left panel under Quality Features, you can enable/disable:

  • Report agent (final summary)
  • Challenger agent (stress-test)
  • Grounding checks (hallucination detection)
Disabling quality features speeds up runs but reduces output reliability. Recommended to keep all enabled for production use.
