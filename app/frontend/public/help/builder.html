Creating a New Ecosystem

Choose ⚙ Builder in the sidebar, then ＋ New ecosystem. You have two paths:

✨ AI-Assisted
Describe what you want in natural language. Tessera suggests a complete ecosystem config — agents, tools, dependencies, memory. Review and accept, then fine-tune.
Manual (Skip)
Start with a blank config and build from scratch. Add agents one by one, wire dependencies, assign tools.

Builder Layout

The builder is a three-column layout:

ColumnContents
Left — Ecosystem ConfigName, description, strategy, quality features, memory, namespaces, inputs
Center — Agent EditorAgent list + detailed editor for the selected agent
Right — PreviewLive graph visualization or generated YAML. Resizable via drag handle.

Ecosystem Settings

Coordination Strategy

  • Orchestrated — agents run in a DAG defined by depends_on. Agents with no dependencies run in parallel.
  • Choreography — event-driven. Agents declare triggers (events they listen to) and emits (events they produce).

Quality Features

  • Report agent — auto-injected final agent that synthesizes all findings into a coherent report
  • Challenger agent — auto-injected agent that stress-tests upstream findings, looking for gaps and contradictions
  • Grounding checks — enables internal + external verification of agent claims

Memory Strategies

Select which memory types agents can use:

  • Semantic — vector-based retrieval of relevant past context
  • Episodic — chronological event memory
  • Summarization — compressed summaries of long interactions
  • User preference — learned user preferences
  • Custom — application-specific memory

Shared Namespaces

Define named memory spaces with read/write permissions per agent. Example: a "shared" namespace writable by analyst agents, readable by all.

Ecosystem Inputs

Define input fields shown to users at launch time. Types: text, file, select. Mark fields as required.

Managing Agents

Adding Agents

Choose + Add Agent. Choose AI-assisted (describe the agent's purpose) or add a blank agent.

Agent Configuration

FieldPurpose
Agent IDUnique identifier (auto-generated, not editable after creation)
Display NameHuman-readable name shown in the UI
SwarmOptional group label — agents in the same swarm run as a parallel unit
Depends onComma-separated list of upstream agent IDs this agent waits for
ToolsComma-separated list of tools this agent can use
Tool budgetsPer-tool call limits. Leave blank to use platform defaults.
System PromptThe agent's instructions — what it does, how it should behave

In choreography mode, additional fields appear: Triggers (events to listen for) and Emits (events to produce).

Clone & Remove

Use Clone to duplicate an agent as a starting point. Use Remove to delete (requires at least one agent).

Tool Budgets

Each tool has a platform default call limit (shown in the editor). You can override per agent:

Tool budgets prevent runaway costs. If an agent hits its budget for a tool, it must proceed without further calls to that tool.

An agent is classified as a synthesizer if it has depends_on (receives upstream output); otherwise it's a leaf.

Graph Preview

The right panel shows a live DAG visualization. Nodes represent agents; edges represent depends_on relationships. You can:

  • Drag edges to rewire dependencies directly on the graph
  • Resize the panel by dragging the left edge
  • Switch to YAML tab to see the generated configuration

Save & Deploy

Choose 💾 Save & Deploy to open the deploy wizard. This:

  1. Validates the ecosystem configuration
  2. Saves the YAML to the backend
  3. Compiles the YAML to a Step Functions state machine (ASL)
  4. The ecosystem becomes immediately available in the Ecosystems view

Loading Existing Configurations

The left panel shows a Load existing section listing all user ecosystems. Choose one to load it into the builder for editing. System-managed ecosystems are excluded (they're not editable).
