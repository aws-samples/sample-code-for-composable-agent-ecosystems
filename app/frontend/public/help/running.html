Starting a Run

Pick an ecosystem and choose Run to open the launch dialog. Tessera shapes the run conversationally — like the Builder — instead of a single mission box:

💬 Mission chat (default)
Describe what you want; the run planner asks one focused question at a time to build a complete brief for this ecosystem. Launch unlocks only once the brief is complete.
📋 Run plan panel
The right-hand panel shows a live briefing checklist (✓ / ○ with progress), the values captured so far, and attached files — so you can see exactly what's gathered and what's still needed.
📎 Attach files (any ecosystem)
Optionally attach files to any run. They're classified and considered in the mission chat, then passed to the agents. Never required.
⌨ Type it myself
Prefer a one-shot mission? Switch to a plain mission box anytime — Launch enables as soon as there's text.
⚡ Dry run
Runs the full pipeline with minimal work — a fast end-to-end test, not for real results.
⚙ Advanced · models
Per-run model selection (profile or per-tier overrides). Run-scoped — never edits the ecosystem. The optimizer may suggest a cost/latency-tuned config.
The planner never invents values — if a detail matters and you haven't given it, it asks. Say "proceed" to leave any remaining details to the ecosystem's discretion.

Run View Layout

When a run is active, the view consists of:

Header Bar
Shows ecosystem name, run status (LIVE / SUCCEEDED / FAILED), and connection state (live WebSocket, polling, or offline).
Activity Strip
Always-visible indicator showing what's happening now: which agents are running, grounding checks in progress, or layer transitions.
DAG Map (left)
Interactive dependency graph. Nodes light up as agents run and complete. Choose any node to focus that agent's output.
Agent Output (center)
Full rendered output for the focused agent — or all agents if none is focused. Supports markdown, charts, tables, cards, and forms.
Agent Cards (bottom)
Horizontal strip of compact cards for every agent. Shows status dot, name, and output preview. Choose a card to focus.
Run Chat (floating)
Floating widget in the bottom-right. Chat with the system during or after a run. Also has an Events tab for raw event inspection.

Activity Strip

The green strip below the header shows real-time activity in priority order:

  1. Agents running — shows agent IDs (clickable to focus). If multiple agents run in parallel, all are listed.
  2. Internal grounding — Amazon Bedrock Guardrails verifying findings against evidence
  3. External grounding — web-search verification of time-sensitive claims
  4. Transitioning — preparing the next layer of agents
If the screen looks idle but the status says LIVE, check the activity strip — grounding checks or layer transitions are likely in progress.

Connection States

Tessera uses WebSocket for real-time events. If the connection drops, it falls back to polling:

IndicatorMeaning
No indicatorLive WebSocket — events stream in real time
◌ pollingWebSocket dropped; polling AWS Step Functions every 5 seconds. Run continues normally.
○ offlineNo connection. Check your network.

Quality Gates & Decisions

Some runs pause at a quality gate — for example a checkpoint reviewer (challenger) flags an issue, or an agent's output needs your call. The gate dialogue leads with the reviewer's actual verdict and the specific concern (not a raw error message), then offers:

  • ✓ Accept — proceed as-is. Records that the concern is accepted so later checkpoints don't re-raise the same thing.
  • ↻ Loop with guidance — re-run with your corrective guidance injected.
  • ✕ Abort — stop the run.

You can discuss the verdict inside the gate before deciding. Gates also surface in the Attention inbox so an away operator is notified; if the pause window elapses, the run ends cleanly rather than crashing.

Run Telemetry & Cost

A floating telemetry widget (and an inline panel in run history) reports per-run and per-agent time, token usage, and an estimated cost (model list prices × tokens). It's an internal estimate for comparing runs/agents — not an authoritative bill. Minimize it to a small icon beside the chat blob.

Notifications — the Attention Inbox

When a run needs you while you're away, it doesn't just wait silently — it posts to the Attention inbox (the ⚠ item in the sidebar). Each entry is a conversation waiting on you:

TypeWhat it is
Quality gateA checkpoint reviewer (challenger) or an output gate paused the run for your decision.
Builder questionThe conversational Builder needs a clarification to continue a design.
Design reviewA proposed design is waiting for your review.
ApprovalAn action is waiting for your approval.

Choose an item to open and resolve it (e.g. Accept / Loop / Abort a gate). Each item carries a deadline: if the pause window elapses before you respond, the item expires and the run ends cleanly (a named GateExpired, not a crash). Resolved or expired items leave the inbox automatically.

Outcome Panel

When a run completes, ecosystems that declare artifacts show an Outcome Panel with each declared deliverable and a Download button (plus a "Download bundle" .zip of the whole run — every output, tool result, and artifact).

If a run finishes but a declared deliverable wasn't produced — or was produced incomplete — the panel shows a degraded warning instead of a misleading clean success. So an empty or partial result is never silently presented as "complete."

Run Chat

The floating chat widget (bottom-right) lets you:

  • Ask questions about the run's findings while it's in progress or after completion
  • View raw events via the Events tab — useful for debugging or understanding agent behavior

Resuming & Re-running

Page reload: if you reload during a run, Tessera resumes tracking automatically — the active run state is persisted to your browser and polling picks up where it left off. You can safely navigate to other views (Builder, Tool Catalog) during a run; choose "⚡ Live Run" in the sidebar to return.

Resume from a step: open Past Runs, choose a run, click any node in its DAG, and select ↻ Resume from here. This starts a new run that reuses every completed upstream step and re-executes from the chosen node onward — so you don't re-run, or re-pay for, work that already succeeded. It works for failed and succeeded runs alike, and a gate-style dialog lets you add guidance before launching. The reused steps show as "carried over" in the new run's DAG.

Native redrive only resumes failed runs from the failure point. "Resume from here" is more general — any node, any run status — and shows you exactly which steps are reused vs re-run before you confirm.
