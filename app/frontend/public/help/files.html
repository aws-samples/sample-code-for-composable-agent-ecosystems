Ecosystem Files

Each ecosystem can have documents attached that agents access on every run. These are persistent — upload once, available for all future runs of that ecosystem.

Access via: select an ecosystem → choose 📁 Files in the action bar.

Uploading Files

Uploaded files are stored in Amazon S3 and may incur storage charges. Remove files you no longer need.

  1. Open the Files modal for your ecosystem
  2. Choose + Upload
  3. Select a file from your computer
  4. Tessera uploads the file to Amazon S3 via presigned URL
  5. Tessera automatically classifies the file (assigns a tag and generates a summary)
  6. Wait for the file to appear in the table once processing completes
  7. Verify the upload succeeded by confirming the file shows a classification tag and summary
Upload reference documents, policies, architecture diagrams, financial reports — anything agents should have access to as context.

How Agents Use Files

When an ecosystem runs, attached files are made available to agents as context. Agents can reference file contents in their analysis and cite them in findings.

Large files may increase agent processing time. Keep uploads focused and relevant to the ecosystem's purpose.

Run-Time File Inputs

Separate from persistent ecosystem files, you can attach files to a single run in two ways — both one-time (not persisted to the ecosystem):

  • Attach files (any ecosystem) — every run dialog has an optional "Attach files" area. Add any file to any run; it's classified and considered in the mission chat (the planner acknowledges and factors it in), then passed to the agents. Never required.
  • Declared file inputs — some ecosystems define typed file-input fields in their configuration (e.g. "upload the 10-K to analyze"). These appear as labelled fields and may be required.
Run-time attachments are classified just like ecosystem files (tag + summary), so the mission planner can reason about them when shaping the run.

Deleting Files

Choose Delete next to any file in the table. A confirmation dialog appears. This action is irreversible — deleted files are permanently removed from S3 and will no longer be available to future runs.
