Agent Types (output_kind)

Every agent has an output_kind that determines its output contract — what it must produce and how it's validated. Set it explicitly in the YAML or let the platform infer it.

KindPurposeRequired Output
analyst Research and analysis agents (default for all agents) ## STRUCTURED FINDINGS section with numbered findings + confidence levels, and ## OPEN QUESTIONS section
synthesizer Agents that combine multiple upstream outputs into a unified view Same as analyst, plus must cite each upstream agent using [per agent_id: ...] markers
challenger Stress-tests upstream findings for gaps and contradictions ## VERDICT (STRONG / ADEQUATE / WEAK) + ## WEAKNESSES section. If any weakness is BLOCKER severity, verdict must be WEAK.
reporter Final synthesis into a coherent prose narrative Prose narrative ≥200 characters. Must NOT contain STRUCTURED FINDINGS (reporters write prose, not bullet lists).
drafter Produces a document (report, memo, policy, etc.) ## SUMMARY header + substantive body (≥100 chars). The actual document format is controlled by output_format.
creative Generates artifacts (code, designs, content) with minimal structural constraints Any non-empty output ≥50 characters. Format validation comes from output_format.
operator Performs actions and reports results (remediation, deployment, configuration) ## RESULT section with status: SUCCESS / FAILURE / DRY_RUN / AWAITING_APPROVAL
chat Conversational agent (used by the Run Chat feature) Any non-empty response

How output_kind Is Resolved

Resolution order (first match wins):

  1. Explicit output_kind field in the agent's YAML config — authoritative
  2. Legacy chat_mode: true — deprecated alias for "chat"
  3. Agent ID heuristics — challenger_agent → challenger, report_agent → reporter
  4. Default: "analyst" — if nothing else matches
Most user-created agents don't need to set output_kind explicitly. The default "analyst" works for research/analysis agents. Set it when you need a different contract (drafter for document generation, operator for actions).

Agent Roles (DAG-derived)

Separate from output_kind, each agent gets a role based on its position in the DAG:

RoleConditionEffect
leafNo depends_onUses leaf model (Sonnet 4). Does primary research via tools.
synthesizerHas depends_onUses synthesizer model (Opus 4). Must cite upstream agents. Gets stronger model for complex reasoning.
challengerID is challenger_agentPlatform-injected. Adversarial review of all upstream.
reporterID is report_agentPlatform-injected. Final prose synthesis.
Synthesizer agents automatically get a more powerful model (Opus 4) because they need to reason over many upstream inputs. Leaf agents use Sonnet 4 since they're primarily tool-driven.

Output Formats

Independent of output_kind, agents can declare an output_format that specifies the file type of their output artifact:

FormatValidationFile Extension
markdown (default)None (free-form).txt
jsonMust contain a valid fenced ```json block that parses successfully.json
yamlMust contain a valid fenced ```yaml block that parses successfully.yaml
htmlMust contain a fenced ```html block (or inline <html>...</html>) with proper open/close tags.html
csvMust contain a fenced ```csv block with ≥1 header row + ≥1 data row.csv
pdfFuture phase.pdf

Configuring output_format in YAML

Add to any agent in your ecosystem YAML:

agents:
  - id: report_writer
    output_kind: drafter
    output_format:
      type: html
      save_as: report.html
      validate: true
    tools: [code_interpreter, web_search]
    prompt: "Generate a comprehensive HTML report..."
FieldPurpose
typeOutput format: markdown, json, yaml, html, csv
save_asFilename for the artifact in S3 (e.g., report.html)
validateWhether to run format validation (default: true for json/yaml/html/csv)
schema_idFuture: reference to a JSON Schema for deeper validation

Artifact Production

Agents can produce artifacts (files) in two ways:

  • Fenced code block — agent writes the artifact inline in its output within a fenced block. The platform extracts and saves it.
  • code_interpreter tool — agent uses code_interpreter to generate the file programmatically. Saved directly to S3 without needing a fenced block.
When save_as is declared and the agent has code_interpreter in its tools, the platform skips fenced-block validation — it expects the artifact to be produced via code.

Combining Kind + Format

output_kind and output_format are orthogonal:

  • analyst + json — produces STRUCTURED FINDINGS in prose, plus a JSON artifact (e.g., structured data export)
  • drafter + html — produces a SUMMARY section plus an HTML document
  • operator + yaml — produces a RESULT status plus a YAML config artifact
  • creative + csv — produces any substantive output plus a CSV data file
